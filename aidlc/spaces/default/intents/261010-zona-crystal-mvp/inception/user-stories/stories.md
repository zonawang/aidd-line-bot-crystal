## Scope & Delivery Order

全部故事為 **Must Have**，全部原功能整合至同一新版。先完成 US8.1 → US8.2 → US9.1 最薄旅程，入口及教學殼一併提供，再補齊其他功能；順序不代表其他故事可延後交付。正式 Unit／MVP 分組在 Delivery Planning 定義。

本文件為待實作的驗收條件，沒有功能或外部通過證據。真實 LINE／模型／持久記憶路徑保留；本機固定例子及替身驗證清楚分列。日期選擇與生命靈數捷徑另外保留，三追問不是整組 Quick Reply 的數量上限。

故事的「依賴」包含建置前置與完成整合關聯：入口、有效生日等前置按單向建置順序安排；文字／圖片、追問、角色、等待、記憶等相互參照是完成時須接起來的行為，不得直接轉成雙向 Unit depends_on。後續 Units Generation 另建立無循環的建置 DAG。獨立驗收可預置回覆、卡片或持久資料；各故事替身測試通過仍不足以取代同一新版的全功能端到端驗證。

## Stories

### US1.1 — 進入同一產品

作為 P1 展示參與者，我想使用本機或 LINE 入口，以便體驗同一組功能。

- 優先：Must Have。來源：FR1、FR1.1、NFR1。
- 依賴：無。
- INVEST：以可觀察行為獨立驗收；技術依賴如上，細部實作可協商，價值如故事句。沿用既有功能可估量並限制於單一行為／失敗復原；不承諾未驗證工時。驗收如下。

- **AC1.1.1** Given 無外部金鑰，When 開啟本機入口並輸入文字，Then 可操作功能且顯示本機教學模式；有設定的 LINE 路徑保留事件與回覆串接。
- **AC1.1.2** Given 有效簽章與平台來源，When 接收支援事件，Then 驗簽後才使用事件中的使用者身分；本機替身驗證事件與回覆呼叫，不當成 LINE 實測。
- **AC1.1.3** Given 簽章缺失／無效或不支援事件，When 接收，Then 無效簽章拒絕且不更新記憶，不支援事件不假造成功諮詢；下一個合法請求仍可處理。

### US3.1 — 重啟後仍有記憶

作為 P1 展示參與者，我想延續必要對話記憶，以便不用每回合重新交代情境。

- 優先：Must Have。來源：FR3、FR3.1、NFR2。
- 依賴：US1.1。
- INVEST：以可觀察行為獨立驗收；技術依賴如上，細部實作可協商，價值如故事句。沿用既有功能可估量並限制於單一行為／失敗復原；不承諾未驗證工時。驗收如下。

- **AC3.1.1** Given A 已輸入虛構生日／收藏並得到文字或圖片描述，When 下一回合詢問先前內容，Then 讀回 A 的必要文字、生日及回覆／描述；不新增保存圖片原檔或秘密。
- **AC3.1.2** Given 資料已寫入實際本機持久儲存，When 停止並重新啟動服務或建立新的讀取實例，再選 A 詢問，Then 仍讀回 A 資料，不用空初始狀態覆蓋；真實持久服務路徑保留。
- **AC3.1.3** Given 無歷史或控制讀寫失敗，When 回憶／保存，Then 分別說明沒有內容、未能讀取或未能保存且可繼續；失敗不宣稱保存完成，下一次可重試。

- **AC9.1.3** Given 圖片無法載入或不存在的選卡識別，When 呈現／選擇，Then 圖片失敗保留文字與動作，未知識別提示重選而不回錯水晶。

### US10.1 — 全功能本機教學頁

### US10.2 — 重現及解說交付

作為 P2 教學分享者，我想依文件啟動、示範、檢查與復原，以便分享可信且可重現的作品。

## Cross-Cutting Acceptance & Test Handoff

NFR1 對應 US1.1、US3.2、US10.1、US10.2；NFR2 對應 US2.1、US2.2、US3.1、US7.1；NFR3 對應 US10.2 的逐需求測試／同命令檢查；NFR4 對應 US10.1；NFR5 對應 US10.2。每個相關 AC 是後續可測條件，不是已執行測試。手機／桌面寬度、圖片限制、有限等待上限及命令在後續最小設計／實作明定。Given／When／Then 不改變已核准 test-after。

品質交接採逐項／參數化驗證：生日各形式、三卡逐卡、三追問逐題及四角色逐組都須實際觸發對應結果；不得只驗按鈕存在。記憶測試使用獨立實際資料位置，A 寫入 → B 隔離 → A 回憶 → 新讀取實例／程序再讀回，教學另演示停止、重啟、再選 A。空歷史、讀取失敗、寫入失敗分開判定，模型、圖片取得及真實記憶讀寫都遵循有限等待；各種受控失敗後再送正常請求確認可恢復。

設計交接維持原生控制、可讀動態狀態、可見焦點及結果附近的範例標示。Refined Mockups 的建議驗證預設為 375／1280 CSS px；由該階段明定手機／桌面清單，不擴充裝置矩陣或新增設計系統。手機三卡可直向排列，追問與額外捷徑可換行；每個選卡動作顯示水晶名稱，素材失敗仍有文字與可操作入口。

US5.1 與教學清單採 spec 四組原輸入：學習「我想提升學習專注力，有什麼水晶建議？」；關係「我想了解愛情與人際關係的水晶搭配」；財運「最近財運起伏，有什麼水晶情境建議？」；鑑定「請介紹水晶基礎鑑定」。每組名稱／頭像均需可重現，本機示例與真實模型分開。
