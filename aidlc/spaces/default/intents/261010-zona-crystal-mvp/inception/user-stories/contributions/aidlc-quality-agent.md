### 關鍵案例與驗證方法

- **日期／數字**：AC8.1.1 的分隔形式及自然語句使用參數化案例，各自驗證同一有效生日；2000-02-29 有效、2001-02-29／2000-02-30 拒絕後修正成功。已核算 AC8.2.2：2000-01-08 的和為 11 → 2；2000-09-29 為 22 → 4；1999-11-12 為 33 → 6。2000-01-01 → 4。不要套用主數保留規則或新增年齡限制。
- **記憶**：使用每個案例獨立的實際本機資料位置與虛構生日／收藏；寫入後釋放原讀取實例，再由新實例或重啟程序讀取。不能只清空變數再讀同一記憶體物件。A 寫入 → B 無 A 內容 → A 可回憶 → 重啟再選 A 可回憶；確認新回合不以空資料覆蓋歷史。AC10.2.4 的不自動刪除與 FR3 的保留至文件重設須帶入最後的儲存／復原驗證。
- **回覆延續**：三卡逐卡選擇及三追問逐題點擊可參數化，驗證傳出的卡 ID／完整題目與呈現結果對應，避免只測按鈕存在。三追問之外保留日期及生命靈數捷徑；替代追問仍須相關且標示來源。
- **四角色**：使用 spec 四組完整原輸入，逐組檢查名稱及對應頭像；未知角色對應「星曜守護導師 艾蓮」。本機固定選擇與真實模型角色結果分列，不能以固定範例推論外部通過。
- **等待及錯誤**：以可控制的成功、拒絕與未回應替身驗證有限逾時與等待清除；每種受控失敗後再送一個正常請求，確認沒有永久鎖住或未處理錯誤。對真實記憶服務的讀寫也沿用 NFR2 的有限等待要求，無須另開新故事。
- **視窗及可達性**：手機／桌面各一個明確寬度可在後續設計自行採最簡預設；主旅程、追問、選單、圖片、A／B、Echo 都需能操作。固定寬度、圖片大小上限、等待上限與正式檢查命令是後續落地值，不是本輪知識缺陷；沒有要求擴充裝置矩陣或取得 WCAG 認證。

### 測試姿態與交付界線

保持已核准 **test-after**：先實作適用可測層，再寫並跑該層測試。Given／When／Then 是驗收表述，並非改採先寫測試。採 Minimal 的逐需求底線與元件正常路徑，加上已核准的實際儲存及最小端到端驗證；不新增自訂 scope 的 80% 目標，不用 CAP 數限制測試量。已有測試與所有適用品質底線須維持通過。
