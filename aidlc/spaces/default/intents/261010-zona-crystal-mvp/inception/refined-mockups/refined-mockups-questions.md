## Design Decisions from Approved Context

沒有新的阻擋性產品問題；按使用者已授權的最簡 MVP-first 方向，採以下介面預設。這些是既有需求的設計細化，不是新增逐題人工作答，也不是已完成介面。

| 設計題目 | 採用方向 |
|---|---|
| 各故事如何呈現？ | 單一對話頁涵蓋 S1–S8；對話旁保留模式／目前 A 或 B、日期／文字／圖片操作，卡片、追問、指南及 Echo 隨狀態出現。教學說明列示範／證據，不增加管理後台。下表逐故事對應。 |
| 互動樣式？ | 原生表單、按鈕、日期／檔案輸入及可收合教學說明；輸入需明確送出。回覆、錯誤及指南都行內呈現，不新增 wizard、modal、拖拉或複雜分頁。 |
| 狀態？ | 空白初始、等待、成功、錯誤、部分可用全部設計。讀寫失敗明示；圖片／頭像／選單素材失敗有文字與動作；真實模式失敗不轉成功範例。 |
| 既有設計系統？ | 未提供可沿用的正式網頁元件庫；以既有 LINE 原生訊息、角色／水晶／雙選單素材為映射來源。本機使用原生 HTML 與少量共用樣式，不採購或新增設計系統。 |
| 無障礙？ | 延續 NFR4：繁體中文、可讀標籤、合理標題／區域、可見焦點、Tab／Enter／Space、圖片文字替代、動態狀態文字。以 AA 常用對比／鍵盤原則指導設計，不宣稱認證或全平台通過。文字對比 4.5:1、控制／焦點 3:1、44 CSS px 操作目標作最小設計細節。 |
| 響應式與驗證寬度？ | 明定手機 375 CSS px、桌面 1280 CSS px。小於 1024 時單欄、三卡直向、追問／捷徑換行；1024 起為對話主欄＋教學側欄，三卡可並排。只驗上述兩個寬度，不擴充裝置矩陣。 |
| 輸出擬真程度？ | 最小中擬真：明確尺寸／順序、真實文案、既有素材位置與動作、必要狀態註記；可用輕量 SVG 或靜態頁示意輔助，不建第二套有後端的 prototype，也不先實作應用程式。 |

## Interaction & Evidence Boundaries

- 模式與目前身分常駐，A／B 切換先結束或等待目前操作完成，避免同一筆回覆被附加到另一身分的畫面；精確資料流程留給最小 Functional Design。
- 等待狀態行內呈現，不鎖整頁或搶輸入焦點；同一操作的重複送出暫停，完成／失敗後恢復。有限等待秒數及圖片大小／格式上限由後續最小設計定義，介面引用實際設定而非自行編造不同值。
- 原生日期控制仍保留文字替代及後端真實曆日檢查；無效日期不新增數字或卡。有效日期後恰三卡、逐卡內容正確；卡片和追問都以明確可讀動作為入口，不依賴圖片／手勢。
- 本機固定文字、固定圖片與 LINE 動作分別就近標示「教學範例回覆」「圖片辨識範例，非真實辨識」「LINE 操作模擬」。技術角色標籤及秘密不顯示於一般對話。
- 補正早期草圖 COSMOS 簡稱、身分操作及驗證寬度；最新已核准 spec／stories 優先，舊文件保留歷史，不回寫其內容。

## Analysis & Product Cross-Check

設計視角採原生操作、單一頁面、可見狀態與錯誤復原；產品視角核對 17 個故事及全功能清單全部有 UI 落點，生日不是諮詢的先決條件，三追問之外捷徑不刪。手機直向卡與桌面教學側欄是本機呈現，不更動 LINE 原生卡片／選單語意。

沒有新的功能、人物、正式部署或營運承諾。responsive 尺寸、對比與操作目標是 NFR4 的最小落地設計，不能聲稱已實測。剩餘套件／儲存／逾時／圖片限制／命令由後續最小設計處理，不為此延長探索。
